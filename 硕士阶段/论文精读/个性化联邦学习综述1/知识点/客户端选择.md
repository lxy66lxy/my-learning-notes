# 客户端选择

**就是决定：这一轮联邦训练，让哪些客户端参与训练并提交更新。**

例如，系统有 **100 部手机**，受通信和计算资源限制，每轮只让 **10 部**参加。那么，就需要决定选哪 10 部。没被选中的手机，可以在后续轮次参与。

最简单的办法是**随机选**。更有针对性的方法，会考虑：

| 选择依据       | 考虑什么                                     |
| -------------- | -------------------------------------------- |
| **数据特点**   | 这些客户端的数据能否覆盖本轮需要学习的内容？ |
| **设备状态**   | 是否在线、电量是否充足、能否及时完成训练？   |
| **通信条件**   | 网络是否稳定，上传更新需要多久？             |
| **参与公平性** | 是否总选同一批客户端，忽略了其他人的数据？   |

结合前面的手写数字例子：

- 甲、乙的数据大多是“1”；
- 丙、丁的数据大多是“7”；
- 戊、己的数据大多是“9”。

如果本轮只选甲、乙，收到的更新就容易偏向数字“1”。如果目标是学习各种数字，可以考虑选择甲、丙、戊，让本轮的数据覆盖更全面。

需要分清：**客户端选择调整的是“本轮谁参加、怎样组合”，并没有直接把各家的数据变成一样。** 选择相似客户端还是互补客户端，要由具体训练目标决定。
